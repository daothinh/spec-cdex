Prompt 1: Bootstrap Outcome + Next Best Attack
=========================================
Use the custom agent `security-bootstrap-pipeline` for this run if it is available in `.codex/agents/security-bootstrap-pipeline.toml`.

Input:
- Program URL or local path: `<url-or-path>`
- Target type if known: `<web|android|smart-contract|native|unknown>`
- Constraints: `<rate limit / no destructive testing / test accounts / scope notes>`
- Extra artifacts: `<burp / caido / apk / contract addresses / docs / audit pdf>`

Focus:
- Bootstrap the target into `audit-targets/<slug>/`
- Choose the primary lane
- Make the lane ready now, or say exactly what blocks it
- End with the next best attack path for hunting

Return only:
- normalized slug and working directory
- chosen primary lane
- follow-on lanes only if they matter
- trust-boundary summary in 3-5 lines
- readiness status: `ready`, `partial`, or `blocked`
- setup attempted and remaining blockers
- first 3 prioritized bug classes
- decisive bootstrap artifacts only, max 5 repo-relative paths
- next best attack path


Prompt 2: TRUE POSITIVE + Severity + Exploit Flow
==================================================
Use the custom agent `security-hunting-pipeline` for this step if it is available in `.codex/agents/security-hunting-pipeline.toml`.

Input:
- Bootstrap target: `audit-targets/<slug>/`
- Constraints: `<rate limit / no destructive testing / test accounts / scope notes>`
- Extra artifacts: `<burp / apk / contract addresses / docs / audit pdf>`

Focus:
- Resume from bootstrap and hunt the highest-value lane first
- Reverify before calling anything real
- Only surface findings that end as `TRUE POSITIVE`
- If nothing reaches `TRUE POSITIVE`, say so and give the next best attack path

Return:
- one-line outcome: `<n> TRUE POSITIVE` or `no TRUE POSITIVE`
- for each `TRUE POSITIVE`:
  - `finding-id`
  - severity, plus CVSS/CWE if already established
  - real observed impact only
  - exploit preconditions
  - exploit flow as short ordered steps
  - decisive replay signal or proof
  - finding bundle path
- blockers before submission, only if a `TRUE POSITIVE` exists
- next best attack path, only if no `TRUE POSITIVE` exists

================================================
Use the custom agent `security-report-submission-pipeline` for this step if it is available in `.codex/agents/security-report-submission-pipeline.toml`.

Inputs:

- Report bundle target: `bug-bounty-reports/<slug>/<finding-id>/`
- Constraints: `<field limits / attachment rules / no upload unless required>`

Focus:
- Build the report bundle from one verified finding
- Submit if possible
- Only report success or the exact blocker
- Do not re-summarize the full report body

Return only:
- status: `submitted` or `blocked`
- channel: `form` or `email`
- report title or email subject
- severity, plus CVSS/CWE if applicable
- confirmation ID, or the exact blocker / validator error
- decisive missing prerequisite, if blocked
- saved report bundle path
- saved `submission.json` or `mail-envelope.json` path
- manual follow-up only if still required
