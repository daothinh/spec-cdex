Prompt 1: Bootstrap Outcome
===========================
Use the custom agent `security-bootstrap-pipeline` for this run if it is available in `.codex/agents/security-bootstrap-pipeline.toml`.

Input:
- Target: `<url-or-path>`
- Constraints: `<scope notes / rate limit / no destructive testing / test accounts>`
- Extra artifacts: `<burp / caido / apk / contract addresses / docs / audit pdf>`

Focus:
- Bootstrap `audit-targets/<slug>/`
- Lock scope, primary lane, readiness, and severity handoff
- Leave hunting with no missing setup context

Return only:
- in-scope summary and out-of-scope reminders that materially affect hunting
- trust-boundary summary in 3-5 lines
- readiness status: `ready`, `partial`, or `blocked`
- first 3 prioritized bug classes
- severity conditions for `medium`, `high`, and `critical`
- decisive bootstrap artifacts only, max 5 repo-relative paths


Prompt 2: Audit + Recon + Hunting -> TRUE POSITIVE + Severity + Exploit Flow
=============================================================================
Use the custom agent `security-hunting-pipeline` for this step if it is available in `.codex/agents/security-hunting-pipeline.toml`.

Input:
- Bootstrap target: `audit-targets/<slug>/`
- Constraints: `<rate limit / no destructive testing / test accounts / scope notes>`
- Extra artifacts: `<burp / caido request IDs or HTTPQL filters / apk / contract addresses / docs / audit pdf>`

Focus:
- Resume from bootstrap and hunt the highest-value lane first
- Audit the in-scope surfaces, do recon, choose attack directions, then hunt
- Compare every candidate against scope before confirming it or assigning severity
- Only `TRUE POSITIVE` findings with final severity `medium`, `high`, or `critical` satisfy the completion bar

Return:
- one-line outcome: `<n> TRUE POSITIVE (medium+)`, `continue-hunting`, or `blocked`
- for each `TRUE POSITIVE` that is `medium+`:
  - `finding-id`
  - real observed impact only
  - finding bundle path
- blockers before submission, only if there is a `TRUE POSITIVE`
- remaining in-scope attack directions and exact blocker, only when outcome is `continue-hunting` or `blocked`


Prompt 3: Automatic Preverify Gate
=========================================
Use the custom agent `security-preverify-trigger` for this step if it is available in `.codex/agents/security-preverify-trigger.toml`.

Inputs:
- Finding bundle: `audit-targets/<slug>/findings/<finding-id>/`
- Optional report bundle target: `bug-bounty-reports/<slug>/<finding-id>/`
- Constraints: `<field limits / attachment rules / no upload unless required>`

Focus:
- Check if the finding is real or AI slop
- Require standalone PoC + decisive logs
- Clear or block report drafting

Return only:
- status: `passed` or `blocked`
- standalone PoC code path
- decisive output-log path
- saved `preverify.md` path
- saved `preverify-gate.json` path
- updated finding-pipeline status


Prompt 4: Submission Success or Exact Blocker
================================================
Use the custom agent `security-report-submission-pipeline` for this step if it is available in `.codex/agents/security-report-submission-pipeline.toml`.

Inputs:
- Submission URL: `<exact form URL>` or recipient email + sender mailbox URL
- Finding bundle: `audit-targets/<slug>/findings/<finding-id>/`
- Report bundle target: `bug-bounty-reports/<slug>/<finding-id>/`
- Constraints: `<field limits / attachment rules / no upload unless required>`

Focus:
- Run preverify first
- Draft only after preverify passes
- Build the final verified report bundle
- Submit if possible
- Report only success or the exact blocker

Return only:
- status: `submitted` or `blocked`
- channel: `form` or `email`
- report title or email subject
- confirmation ID, or the exact blocker / validator error
- saved report bundle path
- saved `submission.json` or `mail-envelope.json` path
- manual follow-up only if still required
